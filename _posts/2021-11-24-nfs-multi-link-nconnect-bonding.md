单条 TCP 连接是 NFS 吞吐的常见瓶颈：一条流受 TCP 流控限制、只走一条 NIC 队列、还是单点故障。要突破它，Linux 这边有三套机制可以叠加：nconnect、session trunking、网卡 bonding。这篇文章讲清它们各自解决什么、怎么叠加，以及无损切换（链路断了业务不中断）是怎么靠这套组合做到的。

## 一、三种机制分别管什么

| 机制 | 层次 | 解决什么 |
|---|---|---|
| nconnect | NFS 客户端 mount 选项 | 一个 mount 开 N 条 TCP 连接，RPC 分散到多条连接上，突破单流吞吐 |
| session trunking | NFSv4.1 协议层 | 一个客户端和服务端之间多个 session，走多条连接 |
| 网卡 bonding | 网络 L2 层 | 多块物理网卡绑成一块逻辑网卡，聚合带宽 + 链路冗余 |

三者层次不同，是叠加关系，不是替代关系。

## 二、nconnect：一个 mount 多条连接

Linux 5.3 起支持 mount 选项 `nconnect=N`，让客户端对一个 NFS mount 建立 N 条 TCP 连接，把 RPC 请求分散到这些连接上。

它解决的核心问题是**单条 TCP 流的吞吐上限**：一条 TCP 连接受拥塞窗口和流控限制，而且通常只被调度到一个 CPU 的一条 NIC 队列上，单流带宽上不去。多条连接就是把请求摊开，绕开单流限制。

一个常见的误区：nconnect 提高的是并发连接的带宽利用，不是无脑翻倍。如果瓶颈在服务端单线程、或者 slot 数已经打满，加连接数也没用。所以 nconnect 要和 slot 数、服务端线程数一起调。

## 三、session trunking：协议层的多 session

NFSv4.1 允许同一个客户端和服务端之间建立多个 session，走多条连接。这和 nconnect 配合时，客户端可以在多个 session 之间分配请求，既提高了并发，也为故障切换留了余地：一条连接断了，请求切到另一个 session 上。

## 四、网卡 bonding：链路聚合和冗余

bonding 在 L2 层把多块物理网卡绑成一块逻辑网卡，Linux bonding 驱动支持多种模式：

- **balance-rr（mode 0）**：轮询发到各物理口，带宽叠加，但可能乱序。
- **802.3ad / LACP（mode 4）**：和交换机配合做链路聚合，带宽叠加且不乱序，是生产里最常用的。
- **active-backup（mode 1）**：主备模式，一块断了另一块接管，冗余优先。

NFS 的连接跑在 bond 出来的逻辑网卡上，就同时拿到了带宽聚合和链路冗余。

## 五、无损切换是怎么组合出来的

把这三层串起来，就能实现"NFS 链路切换业务不中断"：

1. 底层用 bonding（LACP 或 active-backup），单块网卡或单条链路断了，bond 自动切换，上层 TCP 连接不感知。
2. 上层用 nconnect + session trunking，即使某条 TCP 连接真的断了，请求也能切到别的连接或 session 上。
3. NFSv4 的状态（session、delegation、锁）配合 grace period 和状态恢复，让切换期间的服务端故障也能被客户端自愈。

这套组合的难点在于**切换时间要短、且不能丢状态**。我在做无损切换时，目标是把 NFS 的切换收敛到几十秒内，关键就是让底层链路切换和上层状态恢复衔接起来，别让客户端在中间卡死。

## 六、调优和踩坑

1. **nconnect 不是越大越好**。值太大，连接管理开销上升，且如果服务端 slot 或线程数有限，多出来的连接只是空排队。先测出瓶颈在带宽还是在并发，再定 nconnect。
2. **bonding 模式要匹配交换机**。LACP 需要交换机侧也开链路聚合，两边不一致会丢包或环路。
3. **注意乱序**。balance-rr 这种模式会乱序，TCP 对乱序敏感，重传和重排会吃掉带宽，生产里优先 LACP。
4. **RPS/XPS 和中断亲和**。多队列网卡要让队列分散到多个 CPU，否则还是单 CPU 瓶颈。

## 七、小结

NFS 多链路的本质是**分层叠带宽、叠冗余**：nconnect 和 session trunking 在上层铺开并发，bonding 在底层聚合物理链路。要的最终效果是吞吐更高、链路断了能切。调的时候记住各层管各层的：带宽瓶颈调底层，并发瓶颈调上层，故障切换看两层怎么衔接。
